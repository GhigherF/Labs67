# Лабораторная работа: CRUD, SQLite, файловая система и изоляты

## Цель и результат

Приложение использует сущности меню из лабораторной работы № 2 и демонстрирует:

1. Создание, просмотр, изменение и удаление блюд.
2. Постоянное хранение блюд в SQLite через пакет `sqflite`.
3. Поиск по названию и типу блюда.
4. Сортировку по одному или нескольким полям с независимым направлением для каждого поля.
5. Создание, запись и чтение JSON-файлов сущностей в каталогах `path_provider`.
6. Выполнение файлового ввода-вывода в отдельном изоляте Dart.
7. Отображение путей каталогов, уже существующих JSON-файлов и данных, считанных из них.
8. Явное сообщение, если каталог недоступен на текущей платформе.

Основной целевой запуск — Android и iOS. На других системах экран каталогов показывает, какие пути не поддерживаются целевой конфигурацией.

## Сущности

| Сущность | Свойства и назначение |
|---|---|
| `Food` | Базовая сущность блюда: `name`, `weightGrams`; сравнивает блюда по весу и преобразует их в JSON. |
| `Burger` | Бургер: наследует название и вес, содержит калорийность, признак халяльности и `scovilleUnits`. |
| `Soup` | Суп: наследует название и вес, содержит калорийность, признак халяльности и `scovilleUnits`. |
| `Shawa` | Шаурма: наследует название и вес, содержит калорийность и признак халяльности. |
| `Calories` | Контракт калорийности на 100 г и вычисления калорийности порции. |
| `Halal` | Признак `isHalal`. |
| `SpicyMixin` | Уровень остроты и операции над ним для бургера и супа. |
| `Menu` | Коллекция `Food`, реализующая интерфейсы итератора и `Iterable`. |

Названия сущностей также перечислены в самом начале `lib/main.dart`. Модели блюд используются и в SQLite, и в JSON-файлах; отдельные классы-модели для экранов не дублируют предметную область.

## 1. SQLite и CRUD

### Подключённые пакеты

- `sqflite` — асинхронный API SQLite для мобильных платформ.
- `path` — безопасное построение путей к файлам.
- `path_provider` — получение каталогов, назначенных операционной системой приложению.

### Схема БД

`SqfliteFoodRepository` открывает базу `lab2_foods.db` через `getDatabasesPath()`. Таблица `foods` содержит столбцы:

| Столбец | SQLite-тип | Назначение |
|---|---|---|
| `id` | `INTEGER PRIMARY KEY AUTOINCREMENT` | Идентификатор записи; отделён от модели блюда. |
| `type` | `TEXT` | Тип (`Бургер`, `Суп` или `Шаурма`). |
| `name` | `TEXT` | Название блюда. |
| `weightGrams` | `REAL` | Вес порции. |
| `calories100g` | `INTEGER` | Калорийность на 100 г. |
| `isHalal` | `INTEGER` | Булево значение SQLite: `0` или `1`. |
| `scovilleUnits` | `INTEGER` | Острота; для типов без этого свойства сохраняется `0`. |
| `searchText` | `TEXT` | Нормализованные в Dart название и тип для поиска без учёта регистра, в том числе кириллицы. |

При первом открытии пустая таблица заполняется шестью примерами. Повторный запуск не добавляет их снова: seed выполняется только при нулевом количестве записей. Таблица создаётся в `onCreate` с версией схемы `1`.

### CRUD-поток

`FoodRepository` задаёт операции, а `SqfliteFoodRepository` реализует их с помощью SQLite:

- **Create:** форма проверяет поля, создаёт нужный объект `Burger`, `Soup` или `Shawa` и вызывает `insertFood`.
- **Read:** `loadFoods` загружает строки, восстанавливает объект соответствующего класса и возвращает `FoodEntry` с идентификатором БД.
- **Update:** форма редактирования использует тот же экран, что и добавление; запись обновляется по `id`.
- **Delete:** экран сведений запрашивает подтверждение и удаляет запись по `id`.

Общий тип `FoodEntry` связывает первичный ключ SQLite и исходную модель `Food`. Идентификатор не добавляется в доменные классы.

### Страницы и состояние

- **Page1 — список.** После старта загружает записи из репозитория, показывает название, тип, вес и калорийность. Кнопка `+` открывает форму добавления.
- **Page2 — сведения.** Открывается при нажатии на строку; показывает только те свойства, которые предоставляет конкретная сущность, и содержит команды изменения и удаления.
- **FoodFormPage — добавление/изменение.** Один экран обслуживает оба сценария. Проверяются непустое название, положительный вес и неотрицательные целые значения калорийности и остроты.

После успешного изменения или удаления дочерний экран возвращает результат через `Navigator.pop(true)`. Page1 перечитывает данные из БД. Ошибка загрузки показывается на странице списка; ошибка сохранения или удаления — сообщением в интерфейсе.

## 2. Поиск и многополевая сортировка

Поле поиска в Page1 передаёт запрос в репозиторий. SQLite фильтрует `searchText` параметризованным условием `LIKE ?`; запрос не вставляется в SQL как текст. Значение `searchText` формируется в Dart через `toLowerCase()`, чтобы поиск работал и для русских букв.

Диалог **Сортировка** позволяет добавить несколько критериев, поменять их порядок, выбрать поле и переключить направление по каждому. Поддерживаемые поля:

1. название;
2. тип;
3. вес;
4. калорийность;
5. халяльность;
6. острота.

Репозиторий строит `ORDER BY` только из фиксированного enum `SortField`, а не из пользовательского ввода. Поля соединяются в заданном пользователем порядке. Направление критерия — `ASC` или `DESC`; `id ASC` добавляется в конец для стабильного порядка при равных значениях.

## 3. Каталоги Android/iOS

Иконка папки в верхней панели Page1 открывает экран **Файловая система**. Он получает каталоги через `path_provider`, показывает полный путь и список уже существующих JSON-файлов. Кнопка **Записать и прочитать сущности в изолятах** сохраняет разные блюда в доступные каталоги и отображает восстановленные сущности вместе с путями файлов.

| Каталог задания | API `path_provider` | Android | iOS |
|---|---|---:|---:|
| Temporary | `getTemporaryDirectory()` | Да | Да |
| Application Support | `getApplicationSupportDirectory()` | Да | Да |
| Application Library | `getLibraryDirectory()` | Нет | Да |
| Application Documents | `getApplicationDocumentsDirectory()` | Да | Да |
| Application Cache | `getApplicationCacheDirectory()` | Да | Да |
| External Storage | `getExternalStorageDirectory()` | Да | Нет |
| External Cache Directories | `getExternalCacheDirectories()` | Да | Нет |
| External Storage Directories | `getExternalStorageDirectories()` | Да | Нет |
| Downloads | `getDownloadsDirectory()` | Да | Да |

External Storage API предоставляет каталоги, предназначенные для конкретного приложения; код не запрашивает полный доступ ко всему накопителю. Android ограничивает общие каталоги политикой scoped storage, поэтому запись может завершиться ошибкой на устройстве или версии ОС. Такая ошибка выводится с именем платформы, вместо того чтобы отображаться как успешная запись.

Чтобы даже совпадающие системные пути (например, Temporary и Cache) не приводили к перезаписи друг друга, внутри каждого каталога создаётся отдельная папка `uno_lab7_<directory-key>`. В ней используется имя `lab7_<directory-key>.json`. Данные различаются: имя содержит каталог, а вес, калорийность, халяльность и острота формируются для конкретного примера. Это позволяет увидеть, что файлы и сущности в разных местах не совпадают.

Если каталог недоступен на платформе, карточка сообщает, например, `Не поддерживается на Android. Доступно на: iOS.` Если API поддерживается, но ОС не вернула путь или не разрешила операцию, интерфейс показывает фактическую ошибку и текущую платформу. Для множественных каталогов External Storage каждая найденная директория отображается отдельно.

Temporary и Cache предназначены ОС для временных данных и могут очищаться системой. Для постоянных файлов служат Support/Documents. Library — iOS-специфичная директория приложения.

## 4. Изоляты и JSON-файлы

Демонстрация использует `Isolate.run` из `dart:isolate`:

1. Основной изолят создаёт блюдо и преобразует его свойства в JSON-совместимую карту.
2. Для каждого доступного каталога формируется самостоятельный путь и JSON-текст.
3. Изолят получает только строки пути и содержимого, записывает файл через `dart:io File`, затем читает его обратно и декодирует JSON.
4. Изолят возвращает карту — sendable-данные, а не объект Flutter или открытый файловый дескриптор.
5. Основной изолят восстанавливает объект `Food` и показывает его имя и фактический путь.

Точка файлового ввода-вывода вынесена в `_writeAndReadJsonFile`. Ошибки записи/чтения перехватываются для каждого каталога отдельно, поэтому сбой одного пути не прерывает обработку остальных.

Файл можно увидеть в карточке соответствующего каталога после успешной записи или повторного сканирования. На iOS и Android это sandbox каталога приложения, а не обязательно папка, видимая в общем файловом менеджере.

## 5. Ошибки и ограничения платформ

- Каталог сначала сверяется с перечнем поддерживаемых платформ; неподдерживаемый метод не вызывается.
- Сообщение о недоступности называет текущую систему и платформы, где соответствующая возможность предусмотрена.
- Исключения `path_provider`, файловой системы и изолята показываются пользователю с контекстом операции.
- Каталог может существовать, но запись в него может быть запрещена ОС. В этом случае показывается ошибка фактической операции.
- SQLite — мобильная реализация `sqflite`. Windows/Linux/macOS не включены как целевые платформы хранения этого приложения.
- Данные демо-файлов находятся внутри sandbox приложения. Удаление приложения или очистка временного каталога может удалить соответствующие файлы.

## 6. Проверки

`flutter test` проверяет:

- отображение списка и фиксированное `itemExtent: 124`;
- открытие Page2 и свойств сущности;
- добавление записи через форму;
- фильтрацию списка запросом;
- изменение существующей записи;
- удаление записи после подтверждения.

В этих виджетных тестах используется `FakeFoodRepository`, чтобы тесты проверяли UI и навигацию независимо от нативного SQLite-плагина. Реальная реализация `SqfliteFoodRepository` используется приложением на Android/iOS.

## Основные точки входа в код

- `MyApp` выбирает SQLite-репозиторий по умолчанию и допускает передачу тестового репозитория.
- `Page1` отвечает за загрузку, поиск, сортировку и навигацию списка.
- `Page2` отображает свойства модели и запускает изменение/удаление.
- `FoodFormPage` выполняет валидацию и создаёт корректный объект нужного подтипа.
- `SqfliteFoodRepository` открывает SQLite, создаёт таблицу, заполняет начальные данные и выполняет запросы.
- `FileSystemPage` проверяет платформы, показывает директории и запускает файловый сценарий.
- `_writeAndReadJsonFile` выполняет запись и чтение JSON внутри изолята.
